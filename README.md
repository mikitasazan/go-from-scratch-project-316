Разработайте утилиту для обхода и анализа сайтов

Учебный проект Хекслета: https://ru.hexlet.io/programs/go-from-scratch


## Стек

- Go 1.26, [urfave/cli](https://cli.urfave.org/) — разбор аргументов
- Стандартный `net/http` — сетевой клиент передаётся снаружи, чтобы тесты
  обходились без реальной сети
- `golangci-lint`, GitHub Actions

## Установка

```bash
git clone https://github.com/mikitasazan/go-from-scratch-project-316.git
cd go-from-scratch-project-316
make build
```

## Использование

```bash
# обход сайта с настройками по умолчанию
make run URL=https://example.com

# или собранным бинарником
bin/hexlet-go-crawler https://example.com
bin/hexlet-go-crawler --depth 2 --workers 8 https://example.com
```

Без `URL` команда печатает справку и завершается кодом 0.

### Как считается глубина

`--depth` — это число переходов от стартового адреса. Сама стартовая страница
лежит на глубине 0, страницы, на которые она ссылается, — на глубине 1, и так
далее. `--depth 1` означает «только стартовая страница», `--depth 2` — она и
всё, на что она ссылается внутри того же домена.

Ссылки на другие домены не обходятся никогда, независимо от глубины: они
только проверяются на доступность и, если не отвечают, попадают в
`broken_links` той страницы, где найдены. Каждый адрес появляется в отчёте
один раз, сколько бы страниц на него ни ссылалось.

### Ключи

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `--depth` | 10 | глубина обхода |
| `--retries` | 1 | сколько раз повторить неудавшийся запрос |
| `--delay` | 0s | пауза между запросами |
| `--timeout` | 15s | таймаут одного запроса |
| `--rps` | 0 | ограничение запросов в секунду, перебивает `--delay` |
| `--user-agent` | — | свой User-Agent |
| `--workers` | 4 | сколько запросов идёт параллельно |

### Скорость обхода

Ограничение считается на весь процесс, а не на каждого воркера: восемь
воркеров с `--delay=200ms` вместе делают пять запросов в секунду, а не сорок.

- `--delay=200ms` — фиксированная пауза между соседними запросами.
- `--rps=5` — целевое число запросов в секунду. Если заданы оба ключа,
  выигрывает `--rps`.
- Без обоих ключей обход идёт на полной скорости.

В коде за это отвечают поля `Delay` и `RPS` структуры `crawler.Options` — с тем
же правилом приоритета.

### Повторные попытки

`--retries` задаёт, сколько раз повторить запрос сверх первого. Повтор
делается только тогда, когда проблема похожа на временную:

- запрос вообще не дошёл до сервера (сетевой сбой, таймаут);
- сервер ответил `429 Too Many Requests`;
- сервер ответил любым кодом `5xx`.

`404` и прочие постоянные ответы не повторяются — второй раз ответ будет тем
же. Между попытками всегда есть пауза, чтобы не бить по уже перегруженному
серверу; отмена обхода прекращает попытки сразу. В отчёт попадает результат
последней попытки.
