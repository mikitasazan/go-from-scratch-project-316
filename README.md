Разработайте утилиту для обхода и анализа сайтов

Учебный проект Хекслета: https://ru.hexlet.io/programs/go-from-scratch


## Стек

- Go 1.26, [urfave/cli](https://cli.urfave.org/) — разбор аргументов
- Стандартный `net/http` — сетевой клиент передаётся снаружи, чтобы тесты
  обходились без реальной сети
- `golangci-lint`, GitHub Actions

## Установка

```bash
git clone https://github.com/mikitasazan/go-from-scratch-project-316.git
cd go-from-scratch-project-316
make build
```

## Использование

```bash
# обход сайта с настройками по умолчанию
make run URL=https://example.com

# или собранным бинарником
bin/hexlet-go-crawler https://example.com
bin/hexlet-go-crawler --depth 2 --workers 8 https://example.com
```

Без `URL` команда печатает справку и завершается кодом 0.

### Как считается глубина

`--depth` — это число переходов от стартового адреса. Сама стартовая страница
лежит на глубине 0, страницы, на которые она ссылается, — на глубине 1, и так
далее. `--depth 1` означает «только стартовая страница», `--depth 2` — она и
всё, на что она ссылается внутри того же домена.

Ссылки на другие домены не обходятся никогда, независимо от глубины: они
только проверяются на доступность и, если не отвечают, попадают в
`broken_links` той страницы, где найдены. Каждый адрес появляется в отчёте
один раз, сколько бы страниц на него ни ссылалось.

### Ключи

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `--depth` | 10 | глубина обхода |
| `--retries` | 1 | сколько раз повторить неудавшийся запрос |
| `--delay` | 0s | пауза между запросами |
| `--timeout` | 15s | таймаут одного запроса |
| `--rps` | 0 | ограничение запросов в секунду, перебивает `--delay` |
| `--user-agent` | — | свой User-Agent |
| `--workers` | 4 | сколько запросов идёт параллельно |

### Скорость обхода

Ограничение считается на весь процесс, а не на каждого воркера: восемь
воркеров с `--delay=200ms` вместе делают пять запросов в секунду, а не сорок.

- `--delay=200ms` — фиксированная пауза между соседними запросами.
- `--rps=5` — целевое число запросов в секунду. Если заданы оба ключа,
  выигрывает `--rps`.
- Без обоих ключей обход идёт на полной скорости.

В коде за это отвечают поля `Delay` и `RPS` структуры `crawler.Options` — с тем
же правилом приоритета.

### Повторные попытки

`--retries` задаёт, сколько раз повторить запрос сверх первого. Повтор
делается только тогда, когда проблема похожа на временную:

- запрос вообще не дошёл до сервера (сетевой сбой, таймаут);
- сервер ответил `429 Too Many Requests`;
- сервер ответил любым кодом `5xx`.

`404` и прочие постоянные ответы не повторяются — второй раз ответ будет тем
же. Между попытками всегда есть пауза, чтобы не бить по уже перегруженному
серверу; отмена обхода прекращает попытки сразу. В отчёт попадает результат
последней попытки.

## Отчёт

Команда печатает в стандартный вывод один JSON-документ и ничего больше — ни
строки до, ни строки после, только завершающий перевод строки. Всё, что не
относится к отчёту, уходит в stderr, поэтому вывод можно сразу передать по
конвейеру дальше.

```json
{
  "root_url": "https://example.com",
  "depth": 1,
  "generated_at": "2024-06-01T12:34:56Z",
  "pages": [
    {
      "url": "https://example.com",
      "depth": 0,
      "http_status": 200,
      "status": "ok",
      "seo": {
        "has_title": true,
        "title": "Example title",
        "has_description": true,
        "description": "Example description",
        "has_h1": true
      },
      "broken_links": [
        {
          "url": "https://example.com/missing",
          "status_code": 404,
          "error": "Not Found"
        }
      ],
      "assets": [
        {
          "url": "https://example.com/static/logo.png",
          "type": "image",
          "status_code": 200,
          "size_bytes": 12345
        }
      ],
      "discovered_at": "2024-06-01T12:34:56Z"
    }
  ]
}
```

Ключ `error` появляется только тогда, когда есть что в нём написать: у
страницы, которую не удалось прочитать, и у файла, который не удалось
измерить. Остальные ключи стоят в документе всегда.

У страницы, до которой обход не добрался, `assets` и `broken_links` равны
`null`, а не пустому списку: пустой список означал бы, что страницу проверили и
ничего не нашли.

### Поля документа

| Поле | Что значит |
|---|---|
| `root_url` | адрес, с которого начался обход, ровно как его передали |
| `depth` | глубина, с которой обход запускали |
| `generated_at` | момент, когда отчёт собран, ISO 8601 |
| `pages` | по объекту на каждый адрес, который обошли |

Страницы идут от ближних к дальним, а на одном расстоянии — по адресу, так что
два обхода одного сайта дают одинаковый порядок.

### Поля страницы

| Поле | Что значит |
|---|---|
| `url` | адрес страницы |
| `depth` | сколько переходов от стартового адреса до неё |
| `http_status` | код ответа сервера; 0, если ответа не было вовсе |
| `status` | `ok` — страницу удалось прочитать, `error` — нет |
| `error` | почему не удалось; ключа нет, если всё прошло |
| `seo` | что нашлось в разметке: заголовок, описание, `h1` |
| `broken_links` | ссылки этой страницы, которые не отвечают |
| `assets` | файлы, которые страница подгружает |
| `discovered_at` | момент, когда до страницы дошли |

### Поля SEO

`has_title`, `has_description` и `has_h1` отвечают, есть ли на странице
заголовок вкладки, мета-описание и заголовок первого уровня. Рядом с первыми
двумя лежит сам текст — `title` и `description`, обрезанные по краям от
пробелов и переносов. Нет тега — флаг `false`, текст пустой.

### Поля битой ссылки

`url` — адрес, `status_code` — чем ответил сервер, `error` — расшифровка
этого кода или текст сетевой ошибки, если ответа не было вовсе. Ссылки на
чужие домены проверяются, но не обходятся.

Один адрес — одна страница: `https://example.com` и `https://example.com/`
считаются одним и тем же местом и в отчёт попадают один раз. Порт по умолчанию
тоже не делает сайт другим: `http://example.com` и `http://example.com:80` —
один сайт.

Относительные ссылки считаются от того адреса, где страница оказалась после
редиректа, а если в разметке стоит `<base href>` — от него.

### Поля ассета

Список отсортирован по типу, а внутри типа — по адресу, поэтому два обхода
одной страницы дают один и тот же порядок.

`type` — `image`, `script` или `style`. `size_bytes` берётся из заголовка
`Content-Length`, а если сервер его не прислал — файл дочитывается до конца и
байты считаются. Когда размер выяснить не удалось, в поле стоит 0, а причина —
в `error`; там же оказывается расшифровка кода, когда файл отвечает 400 и выше.

Один и тот же файл запрашивается ровно один раз, сколько бы страниц на него ни
ссылалось, и во всех этих страницах его данные совпадают. Сами ассеты не
обходятся как страницы: ссылок из них не берётся.

### Отступы

Флаг `IndentJSON` структуры `crawler.Options` управляет только расстановкой
пробелов и переносов. Набор ключей, их порядок и значения от него не зависят.
Команда всегда печатает документ с отступами — так его читают глазами; вызов
библиотеки решает сам.
